# 鲤慧 LiHui · 真实价格接口接入指南

> 目标：让商城从「示例目录 + 参考价」升级为「百度真实店铺 + 携程/美团真实价」。
>
> 本文档只讲三件事：**数据从哪来**、**价格怎么接**、**没接 key 时怎么处理**。

---

## 一、数据的两个来源（小程序里是两个 tab）

| tab | 数据源 | 怎么做的 | 适合场景 |
| --- | --- | --- | --- |
| **附近真实** | 百度地图 `place/v2/search`，按你的坐标 3km 实时检索 | `services/catalog.js` | 想知道"我楼下有什么店" |
| **郴州热门** | 百度地图，用郴州高频关键词（东江湖 / 莽山 / 裕后街 …） | `services/catalog.js` | 想出去玩，不知道去哪 |

**真实的部分**：店名、地址、坐标、行政区、电话、距离 —— 全部来自百度 POI，不是写死的。
**不真实的部分**：价格。百度 place 接口只给"店"，不给"价"。

### 关于百度配额（重要）

`place/v2/search` 是**日配额**计费的，超限后返回 `302 天配额超限，限制访问`，当天后续请求全部拿不到数据。

- 本项目一次同步最多 ~10 次检索，目录落盘后缓存 **1 小时**（`CATALOG_TTL`），切 tab 不会重新打百度。
- 命中配额时接口会返回 `quotaHit: true` 和一句人话说明，前端会显示黄色提示条，**不会白屏**。
- 如果你每天同步次数多、配额老是不够：
  1. 去 [百度地图开放平台](https://developers.map.baidu.com/) 提升 AK 的日配额（企业认证额度更高）；
  2. 或者把 `CATALOG_TTL` 调大（在 `src/services/catalog.js` 顶部）；
  3. 或者把热门城市的目录**预生成一份 JSON 放进仓库**，构建时 COPY 进镜像（`Dockerfile` 里加一行 `COPY 03-lh-server/data/catalog.json ./data/catalog.json`）。

## 二、价格怎么接（这一步需要你的 key）

### 现状

- 没配 key 时：商城显示「参考 ¥160/晚 起」，**前端会打「参考价」角标**，详情页底部会说明真实价要去平台看。
- 配了 key 时：详情页自动换成「真实价 ¥XXX」并去掉参考角标，订单金额按真实价算。

### 接入方式：填环境变量，**不改代码**

适配层在 `src/services/supplier.js`，请求模板（URL / 方法 / Header / Body / 返回字段路径）全部由环境变量驱动，
所以不管接携程、美团、飞猪、自建中台还是你自己搭的代理，都是同一套配置。

#### 携程（酒店房价 / 门票）

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `CTROP_APP_ID` | ✅ | 开放平台应用 ID |
| `CTROP_APP_KEY` | ✅ | 应用密钥（也用来算 `{{sign}}`） |
| `CTROP_URL` | ✅ | 真实价格查询接口地址，**填了才算启用** |
| `CTROP_METHOD` | | `GET` / `POST`，默认 `POST` |
| `CTROP_BODY` | | Body 模板，支持变量（见下表） |
| `CTROP_AUTH` | | 鉴权值，如 `Bearer {{appKey}}` |
| `CTROP_HEADERS` | | 额外 Header 的 JSON |
| `CTROP_PRICE_PATH` | | 返回里价格的 JSON 路径，默认 `data.price` |
| `CTROP_TITLE_PATH` | | 返回里标题的 JSON 路径（可选） |
| `CTROP_URL_PATH` | | 返回里商品页链接的 JSON 路径（可选） |
| `CTROP_TTL` | | 结果缓存毫秒，默认 300000（5 分钟） |

#### 美团（到店餐饮 / 团购 / 上门服务）

把前缀换成 `MEITUAN_` 即可：`MEITUAN_APP_ID` / `MEITUAN_APP_KEY` / `MEITUAN_URL` / …

#### Body 模板里可用的变量

| 变量 | 含义 |
| --- | --- |
| `{{keyword}}` | 供应商关键词（= 真实店名，跳平台能直接搜到同一家） |
| `{{name}}` | 店名 |
| `{{city}}` | 城市（百度 POI 给的） |
| `{{lng}}` / `{{lat}}` | 店铺坐标（GCJ-02） |
| `{{uid}}` | 百度 POI uid |
| `{{appId}}` / `{{appKey}}` | 你的应用凭据 |
| `{{sign}}` | Body 的 HMAC-SHA1（大写 hex），常见于各家开放平台签名 |
| `{{md5}}` | Body 的 MD5 |

**示例**（假设你自己的代理接口）：

```bash
CTROP_URL=https://your-proxy.com/api/price
CTROP_METHOD=POST
CTROP_AUTH=Bearer {{appKey}}
CTROP_BODY={"city":"{{city}}","keyword":"{{keyword}}","ts":"{{ts}}","sign":"{{sign}}"}
CTROP_PRICE_PATH=data.hotel.lowestPrice
CTROP_TTL=600000
```

### 第三步：把 key 放进服务端

云托管是**从 Gitee 拉仓库 build 镜像**的，顺序必须是：

1. 改好环境变量并 push 到 Gitee（或直接在云控制台「环境变量」里填）
2. 云控制台点 **发布** 重新构建
3. 发布后访问 `GET /api/v1/shop/suppliers` 看 `enabled` 是不是 `true`

> ⚠️ 只改本地 `.env` 不起效，云上跑的是镜像里的 `.env.cloud`。

### 提交订单时会发生什么

1. 鲤慧创建订单，**金额按真实价**（拿不到就用参考价，且订单里带 `priceEstimated` 痕迹）
2. 弹出「去支付」→ 跳携程/美团小程序，用**真实店名**当关键词
3. 在第三方平台看到真实房价、完成付款 —— 鲤慧不接触资金，只留痕

## 三、门店外卖平台「联网识别」（美团 / 饿了么 / 抖音）

> 诉求：每个附近门店要能识别「在不在美团/饿了么/抖音、什么价、什么评分」。

### 硬约束（必须先说清楚）

美团 / 饿了么 / 抖音 **没有公开的店铺检索 API**：

- 数据在各自 App 内，开放平台要**商户号 / 渠道资质**才能调；
- 爬取违反 robots + 用户协议，且微信小程序审核过不了；
- 所以**服务端不能逐店自动拉取真实在架状态 / 价格 / 评分**。任何「自动识别」只能来自你自配的真实接口。

⚠️ 因此本能力**默认是「引导式识别」，不是「服务端自动识别」**——这是合规边界，不是偷懒。

### 两层设计（诚实、不编造数据）

**① 静态层（零网络，目录构建期落库）**

`services/catalog.js` 的 `mapPoi` 给每个门店挂 `platforms` 字段：

```jsonc
"platforms": {
  "meituan": { "name":"美团", "searchUrl":"https://www.meituan.com/search/?query=零食很忙",
               "verified":false, "onShelf":null, "price":null, "rating":null, "source":"link" },
  "eleme":   { ... 同上，searchUrl=https://www.ele.me/search/?keyword=... },
  "douyin":  { ... 同上，searchUrl=https://www.douyin.com/search/...?type=poi }
}
```

- `verified:false` / `onShelf:null` = 尚未经真实接口核实；
- `searchUrl` = 平台「搜这家店」的**公开网页**深链（非 API，仅跳转，合规可用）；
- 前端渲染成「去美团 / 饿了么 / 抖音看看这家店」三个按钮，用户点开即见平台**实时**在架/价格/评分。

**② 实时层（按需 `/shop/identify`，配了 `*_URL` 才联网）**

```
GET /api/v1/shop/identify?id=b_xxx
→ { id, name, platforms: { meituan:{ onShelf, price, rating, url, verified, searchUrl }, ... } }
```

- 配了 `MEITUAN_URL` 等真实接口 → 真的去拉，拉到：`verified:true` + `onShelf:true` + `price` + `rating` + 真实 `url`；
- 接口通但查无此店：`verified:true` + `onShelf:false`（明确「未上架」）；
- 没配 key：`verified:false` + 回落深链。**绝不返回假在架 / 假价格。**

`*_URL` 的请求模板与价格接口完全一致（见上表），只是多一个 `RATING_PATH` 取评分；`searchUrl` 可用 `*_SEARCH_URL` 覆盖默认深链。

### 前端怎么用

- 门店详情页读 `item.platforms`，给每个 `delivery` 平台渲染一行：图标 + 「去{name}看看」按钮（跳 `searchUrl`）；
- 想「自动核实」时调 `/shop/identify`，若返回 `verified:true` 则该平台显示 `onShelf`/`price`/`rating` 徽章。

## 四、能力边界（说清楚，别误判）

| 想要的能力 | 能不能 | 为什么 |
| --- | --- | --- |
| 真实店铺（店名/地址/电话/坐标） | ✅ | 百度 place 接口 |
| 距离、导航 | ✅ | 百度 POI 坐标 + 距离排序 |
| 真实房价/菜单价/库存 | ⚠️ 需你提供 key | 携程/美团开放平台要商家或服务商资质 + 商务签约，产品本身拿不到 |
| 鲤慧自己收钱扣款 | ❌ | 需要支付牌照 + 商户号，不在产品范围内 |
| 自动替用户完成第三方支付 | ❌ | 涉及账号授权与风控，只能跳过去让用户自己付 |

所以「下单」的准确说法是：**鲤慧真实选品 + 真实留痕 → 跳第三方看真实价并支付**。

## 六、新增接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/shop/sync?mode=near\|hot&lng=&lat=&force=1` | 强制重建真实目录（会打百度） |
| `GET /api/v1/shop/source?mode=&lng=&lat=&category=&keyword=` | 取列表（走缓存，省配额） |
| `GET /api/v1/shop/price?id=b_xxx` | 拉真实价，没 key 返回参考价 |
| `GET /api/v1/shop/suppliers` | 各渠道接入状态（前端显示"已接/未接"） |
| `GET /api/v1/shop/identify?id=b_xxx` | 联网识别门店在各外卖平台的在架/价格/评分（见第三节） |
