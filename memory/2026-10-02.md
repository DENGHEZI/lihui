## ★ Gitee push 卡死的真凶：Git Credential Manager 在后台挂起（必看）
现象：`git push origin master` **挂住 10 分钟无输出**（后台/前台都卡），
`GIT_TERMINAL_PROMPT=0` 也挡不住；`git ls-remote` 却秒回（读操作不需要凭据）。
- `GIT_TRACE=1 git push` 定位到卡在：
  `start_command: .../PortableGit/versions/1.2.0/mingw64/bin/git-credential-manager.exe get`
  （从发起起 20s+ 不返回 = GCM 在等 GUI 交互，而 Agent 的后台进程没有桌面会话）。
- 绕过验证：`GIT_TERMINAL_PROMPT=0 git -c credential.helper= push origin master`
  → `fatal: could not read Username for 'https://gitee.com'`（说明凭据确实没喂上）。
- ✅ **正确解法（已实测，不用再问用户要令牌）**：凭据本来就在 Windows 凭据管理器里，
  直接 `credential fill` 读出来拼成 URL 推：
  ```bash
  CRED=$(printf 'protocol=https\nhost=gitee.com\n' | GIT_TERMINAL_PROMPT=0 \
         git -c credential.helper="manager" credential fill)
  TOKEN=$(echo "$CRED" | sed -n 's/^password=//p')
  GIT_TERMINAL_PROMPT=0 git -c credential.helper= push \
    "https://deng-he-ziyan:${TOKEN}@gitee.com/deng-he-ziyan/lihui.git" master
  ```
  → 秒回 `7023569..c0fdb52  master -> master`（5 秒）。推完记得删临时凭据文件。
  **记住这一条就够了**：`credential.helper=manager` 只用来「读」凭据，推送时用 `credential.helper=` + 凭据拼 URL。
- 本机 Git 凭据：`credential.helper` = PortableGit 自带的 `git-credential-manager.exe`（存在但后台会挂）。

## ★ GitHub「推了却看不见代码」= 默认分支是 main，你推的是 master（本轮踩到）
建仓时 GitHub 生成空 **`main`** 分支并把它设为 default_branch，我 `push … master` 成功，
但用户打开仓库首页看的是 **main**（空）→ 他判定「github 没有代码」。
- 修法两步：
  1. `PATCH /repos/{owner}/{repo} {"default_branch":"master"}`（PAT 只需 `repo`）
  2. `git push --force <githubURL> master:main`（main 上是建仓空提交，非快进，必须 force）
- 验证：`git ls-remote` 看两边 ref；`api.github.com/repos/.../git/trees/main?recursive=1` 数文件。
- **以后推 GitHub：先确认 default_branch**，或干脆两个分支都推（master + main）。

## ★★ README 图片「一片空白」的真因：markdown 图片语法被格式化成纯文本（踩过两次）
现象：Gitee / GitHub 上 README 能看见文字和左侧目录，但**每张图的位置都是空白**。
排查：先 `grep -oE "docs/screenshots/[^)]+\.(jpg|png)" README.md | sort -u | wc -l`，
结果是 **0 或很少** → 不是图床缓存、不是 CDN、也不是没推，是 **`![alt](path)` 被某个环节改写成了纯文字**
（表格里只剩下「地图主页 / 15分钟圈 / 我的订单」这种字符串）。
- 修：手动把 `![alt](docs/screenshots/xx.jpg)` 写回单元格，顺便补 alt（利于搜索）。
- 事后自检：`grep -oE "docs/screenshots/.+" README.md | sort -u | wc -l` 必须 == 截图实际张数。
- **本项目 README 每次改完都要过一遍这个计数**，别只看页面截图判断「图有没有了」。

## ★ Gitee README「没更新」通常是缓存不是没推
Gitee 远端 `ls-remote` 已是新 commit 但页面显示旧 README = **浏览器/CDN 缓存**，
Gitee **没有**刷新 README 缓存的 API，只能让用户 `Ctrl+F5` / 无痕窗口，
或等 CDN（几十秒～几分钟）。判断顺序：**先 `git ls-remote` 确认远端，别急着反复推。**
