# 鲤慧 · 产品与架构设计说明书

- 文档版本：v1.0
- 产品名称：**鲤慧**（英文 LiHui）
- 定位：基于百度地图开放能力，面向「老年人 + 青年人」双人群的 **15 分钟生活圈智能体检与规划助手**
- 对应赛题：百度地图赛题 —— 基于地图开放能力的"15 分钟生活圈"智能体检与规划助手

---

## 1. 产品目标

一句话：**让用户在 15 分钟步行半径内，把「看病、买菜、办事、遛弯、吃饭」一次性规划清楚，并且算得清花了多少钱。**

三个可量化的设计指标：

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| 首次可用时长 | ≤ 8 秒（冷启动到看到自己所在位置与周边 POI） | 端上埋点 `t_first_useful` |
| 生活圈体检报告生成 | ≤ 3 秒（服务端 6 类设施聚合计算） | `/api/v1/life/report` 耗时 |
| 单次对话平均 Token 成本 | ≤ ¥0.02（默认轻量模型） | `tokenMeter` 记账 |

---

## 2. 双人群设计（赛题明确要求「老年人、以及青年人」）

| 维度 | 关怀模式（老年人） | 标准模式（青年人） |
|---|---|---|
| 字号 | 正文 18px+，按钮 20px+ | 正文 15px |
| 对比度 | ≥ 7:1（WCAG AAA） | ≥ 4.5:1（AA） |
| 交互 | 全语音、单步引导、结果一次只推 1 条 | 多轮对话、批量列表、地图叠加 |
| 语音 | 语速 0.8x，音量 1.2x，方言可选 | 语速 1.0x，可关闭播报 |
| 默认页 | 一键「我要去哪儿」大按钮 | 地图主页 + 搜索框 |
| 安全 | 涉及支付/跳转必须二次语音确认 | 一次确认 |

> 实现：端上 `settings.careMode` 布尔开关，全局注入 `body.care` 类；
> 服务端 Agent 收到 `careMode=true` 时自动切换到短句、慢速、少选项的回复模板。

## 3. 分层架构

### 3.1 客户端层（薄客户端）

职责只有 4 件事：**渲染地图底图、采集位置/语音、呈现结果、上报埋点**。

- 多端 APP（uni-app）：`<map>` 组件渲染底图；位置用 `uni.getLocation`；语音用 `uni.getRecorderManager` + 服务端 TTS。
- 小程序（原生）：`<map>` + `wx.getLocation`；百度 AK 直连用于小程序侧的行政区/POI 兜底。
- 客户端**不持有**服务端 AK，**不做**模型调用。

### 3.2 服务端层（能力中转 + 编排）

```
HTTP 入口  src/app.js (node:http)
   ├─ 中间件：CORS → 设备指纹 → 限流 → Token 计量
   ├─ routes/  REST 路由
   ├─ services/
   │    ├─ baiduMap.js    百度地图 Web 服务 API 封装（统一鉴权、重试、缓存）
   │    ├─ ipLocate.js    IP 自动锚定
   │    ├─ agent.js       Agent 编排（= MCP Client）
   │    ├─ mcpHub.js      MCP Server 生命周期
   │    ├─ modelRegistry.js 用户自定义模型
   │    ├─ voice.js       自定义语音
   │    ├─ tokenMeter.js  Token 记账
   │    └─ store.js       本地 JSON 持久化（data/*.json）
   └─ mcp/
        ├─ client.js      MCP Client（JSON-RPC over stdio）
        └─ servers/       内置 MCP Server 实现
```

### 3.3 MCP 工具层

每个 MCP 协议 = 一个 MCP Server，独立进程、独立 `package.json`、可单独发布到 ModelScope 或从
ModelScope 拉取。Agent 侧只做 `tools/list` 能力发现与 `tools/call` 调度。

## 4. 关键流程

### 4.1 冷启动 & IP 自动锚定

```
App 启动
  └─ 请求 GET /api/v1/ip/locate
       ├─ 服务端读 X-Forwarded-For / X-Real-IP / socket.remoteAddress
       ├─ 命中缓存(30min) → 直接返回
       └─ 未命中 → 百度 IP 定位 API (ak=服务端AK&coor=bd09ll&ip=…)
            → 落缓存 → 返回 { ip, city, province, point:{lng,lat}, isp }
  └─ 客户端立即用返回坐标做一次「周边 POI 预取」→ 首屏即有内容
  └─ 若 IP 库精度不足（confidence < 0.5）→ 端上再调 uni.getLocation 做 GPS 校正
```

### 4.2 Agent 对话（MCP Client 编排）

```
POST /api/v1/agent/chat  { sessionId, text, careMode, plan }
  ├─ 1. 意图识别（轻量模型 / 规则兜底）
  ├─ 2. 工具选择：mcpHub.list() 过滤 plan 许可 → LLM function-calling 选工具
  ├─ 3. tools/call（可并行）：
  │       ip-anchor.locate → baidu-map.poi_search → life-circle.diagnose
  │       → cost-optimizer.optimize_plan → emotion.soothe(按需)
  ├─ 4. 结果汇总 → 生成人性化回复（概览式、分点、短句）
  ├─ 5. 成本优化后处理：若涉及出行/采购，强制附「省钱方案对比」
  └─ 6. tokenMeter.record(usage) → 返回 { reply, cards[], actions[], usage }
```

### 4.3 15 分钟生活圈体检

以用户坐标为圆心，按 6 类设施分别做等时圈查询（`walking` 半径 1200m ≈ 15 分钟）：

| 类别 | 关键词 | 权重 | 达标线 |
|---|---|---|---|
| 医疗 | 医院/社区卫生服务中心/药店 | 25% | ≥ 2 类 |
| 教育 | 幼儿园/小学/中学 | 15% | ≥ 1 类 |
| 商业 | 超市/菜市场/便利店 | 20% | ≥ 2 类 |
| 餐饮 | 餐厅/早餐店 | 10% | ≥ 3 家 |
| 交通 | 公交站/地铁站/停车场 | 20% | ≥ 1 类 |
| 休闲 | 公园/健身路径/文体中心 | 10% | ≥ 1 类 |

总分 = Σ(类别得分 × 权重)，输出 0–100 分 + 短板清单 + 补齐建议（去哪个方向、多远）。

## 6. 非功能设计

| 项 | 方案 |
|---|---|
| 安全 | 服务端 AK 不下发；端上只持有设备指纹；写接口限频 60 次/分钟/设备 |
| 容错 | 百度 API 失败 → 本地静态降级数据（内置 8 城示例 POI）；MCP 进程崩溃 → 自动重启 ≤ 3 次 |
| 缓存 | 逆地理 24h、POI 搜索 5min、IP 定位 30min、路线 1min |
| 可观测 | 每个请求带 `X-Trace-Id`，结构化日志落 `data/logs/YYYY-MM-DD.log` |
| 成本 | 默认轻量模型；`cost-optimizer` 在结果层做「省钱优先」重排 |
| 合规 | 定位前必须弹隐私授权；IP 只取到城市级，不落库原始 IP |
